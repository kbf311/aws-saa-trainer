# プロンプト：AWS SAA-C03 練習問題の新規作成（汎用テンプレート）

以下の指示に従って、AWS SAA-C03（ソリューションアーキテクト - アソシエイト）レベルの練習問題を新規作成してください。

作成にあたっては、別紙 **`prompts/category_topics.md`** に定義されている各大分類・中分類の情報（保存先ディレクトリ、主要AWSサービス、頻出テーマ・観点）に厳密に準拠します。

---

## 1. 今回作成する対象中分類の指定

ユーザーから指定された「中分類（`minor_id` または 中分類名）」に基づき、`prompts/category_topics.md` から該当する以下のパラメータを特定して適用してください：

- **大分類名 (`category_major`)**: （例: `レジリエント・アーキテクチャの設計`）
- **中分類名 (`category_minor`)**: （例: `ディザスタリカバリ`）
- **保存先ディレクトリ**: （例: `data/questions/resilient/disaster_recovery/`）
- **作成問題数**: ユーザー指定の問数（未指定の場合はデフォルト 3問）

---

## 2. ファイル命名規則とIDのルール（重要）

- **AI側でUUIDを生成する必要はありません。**
- 作成するファイル名および JSON内の `"id"` は、該当ディレクトリ内の既存ファイルに続く **3桁の連番** で作成してください。
  - 例: すでに `000`（`sample.json`）、`001`, `002` がある場合 ➔ `003.json`（中身の `"id": "003"`）、`004.json`（中身の `"id": "004"`）
  - ※作成後に人間（ユーザー側）が同期スクリプト（`run_sync_questions.bat`）を実行することで、一括して正式な UUIDv4 への変換および `index.json` / `categories.json` の再生成が行われます（AI側で本スクリプトを実行する必要はありません）。

---

## 3. 参照サンプル（雛形とJSONスキーマ）

各ディレクトリ内の `sample.json` をスキーマの雛形として参照してください。

```json
{
  "id": "003",
  "category_major": "指定された大分類名",
  "category_minor": "指定された中分類名",
  "title": "簡潔で分かりやすい問題の要約タイトル",
  "services": [
    "主要AWSサービス1",
    "主要AWSサービス2"
  ],
  "question_type": "single",
  "question_text": "ある企業が〜（具体的なビジネスシナリオ、非機能要件、制約条件を提示）〜最も適切なソリューションはどれですか？",
  "options": [
    {
      "id": "A",
      "text": "選択肢Aのテキスト...",
      "explanation": "選択肢Aが不正解（または不適切）となる具体的な理由（コストが高い、要件を満たせない、運用オーバーヘッドが大きい等）。"
    },
    {
      "id": "B",
      "text": "選択肢Bのテキスト...",
      "explanation": "選択肢Bが正解となる具体的な理由、技術的なメリット、要件との合致点。"
    },
    {
      "id": "C",
      "text": "選択肢Cのテキスト...",
      "explanation": "選択肢Cが不正解となる理由。"
    },
    {
      "id": "D",
      "text": "選択肢Dのテキスト...",
      "explanation": "選択肢Dが不正解となる理由。"
    }
  ],
  "correct_answers": [
    "B"
  ],
  "explanation": "本問全体の解説・アーキテクチャの設計原則・AWSベストプラクティス・関連知識のまとめ。"
}
```

### 【超重要】解説文 (`options[].explanation` および `explanation`) の記述ルール
- **選択肢ごとの解説 (`options[].explanation`)**:
  - 各選択肢が「なぜ正解なのか」または「なぜ不正解（不適切）なのか」を1対1で明確に記述してください。
  - 出題時に選択肢の表示順がランダムにシャッフルされるため、解説文内に「選択肢Aは〜」「正解はBです」といった固定記号は含めず、その選択肢の技術・構成内容に基づいて記述してください。
- **全体解説 (`explanation`)**:
  - 個別選択肢の解説ではなく、設問シナリオ全体のアーキテクチャ設計原則、AWSベストプラクティス、トレードオフの要点を記述してください。

---

## 4. 既存問題の傾向確認とトークン節約ルール

1. **まず対象ディレクトリの `index.json` を確認する**:
   - 例: `data/questions/{major}/{minor}/index.json` を開き、既存問題の `title`（タイトル）および `services`（関連サービス）から、すでに出題済みのテーマや傾向を把握してください。
2. **トークン節約の徹底（個別ファイルは原則閲覧禁止）**:
   - AIのトークン消費を最小限に抑えるため、**個別の問題JSONファイル（`*.json`）の問題文本文は原則として読み込まないでください**。出題重複のチェックは `index.json` のみで行ってください。
3. **主要テーマを網羅した後の「類似問題作成」指示**:
   - `category_topics.md` の主要テーマをおおよそ出し尽くした（網羅した）場合は、**「類似問題（応用・バリエーション問題）」**を作成してください。
   - **目的**: ユーザーが問題文や選択肢の並びを単に丸暗記してしまい、本番試験で応用が利かなくなるのを防止するため。
   - **バリエーションの作り方**:
     - **制約条件の反転・変更**: 例：「コスト最小化を最優先」➔「ダウンタイム許容ゼロへ要件変更」
     - **規模・ワークロードの変更**: 例：静的コンテンツ配信 ➔ 大規模トランザクションを伴う金融・EC
     - **代替サービスの比較**: 例：Aurora Global Database と DynamoDB グローバルテーブルの使い分け
   - **元の問題ファイル閲覧の例外許可**:
     **類似問題・応用問題を作成する場合に限り、元ネタとなる個別問題JSON（1〜2ファイル程度）を直接開いて参照・比較して構いません。**

---

## 5. 出題品質のガイドライン

- **実務・試験シナリオに即した設問**: 単なる用語の知識を問うのではなく、「企業が直面している課題・制約（コスト最小化、運用管理負担の軽減、厳しいRTO/RPO、急激なトラフィック急増など）」を具体的に設定してください。
- **選択肢の妥当性**: 不正解の選択肢も「存在しない機能や架空のサービス」ではなく、「技術的には可能だが要件を満たさない」「コストが高すぎる」「運用オーバーヘッドが大きい」といったSAA試験らしい実践的な理由で誤りとなるようにしてください。
- **丁寧な解説 (`explanation`)**: なぜその選択肢が最適なのか、なぜ他の選択肢では要件を満たせないのかを各アプローチごとに明記してください。
- **設問形式 (`question_type`)**:
  - 単一選択: `"question_type": "single"`, `"correct_answers": ["B"]`
  - 複数選択: `"question_type": "multiple"`, `"correct_answers": ["A", "C"]`（問題文末尾に「（2つ選択してください）」等を明記）

---

## 6. 禁止・注意事項

- `data/questions/{major}/{minor}/index.json` は **手動で編集しないでください**（スクリプトで自動再生成されます）。
- 各フォルダの `sample.json` は **編集・削除しないでください**。
